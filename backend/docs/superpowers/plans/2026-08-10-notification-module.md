# Generic Notification Module Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a generic, domain-agnostic `App\Modules\Notification` module that lets any module send a Laravel notification to one or many users by id, without wiring it into any specific caller yet.

**Architecture:** A hand-created Laravel module (no `php artisan module:make`, matching the existing `Shared` module) with only `Domain/Contracts` (interface) + `Infrastructure` (implementation) + `Providers` layers — no HTTP/Presentation layer, no routes. `NotificationSenderInterface::send(array $userIds, Notification $notification): void` is the sole contract; the implementation resolves `App\Modules\User\Infrastructure\Models\User` rows by id and dispatches via Laravel's `Notification::send()` facade.

**Tech Stack:** PHP 8.4, Laravel 13 (`illuminate/notifications`), nwidart/laravel-modules, Pest 4.

## Global Constraints

- Module is hand-created, not via `php artisan module:make` — matches the existing `Shared` module's shape (Domain + Infrastructure + Providers only, no `Presentation/`, no routes).
- The interface only exposes `send(array $userIds, Notification $notification): void` — no separate single-user method.
- Ids in `$userIds` that don't match an existing user are skipped silently (best-effort, no throw). An empty `$userIds` array is a no-op.
- `NotificationSender` depends directly on `App\Modules\User\Infrastructure\Models\User` (cross-module dependency, same precedent as Vendor→User) — no morph map or abstraction layer.
- Binding happens in `NotificationServiceProvider::register()`, matching `UserServiceProvider`'s style (no `$providers` property, just `parent::register()` + `$this->app->bind(...)`).
- Test file is Pest, function-style (`test(...)`, top-level helper functions), `uses(RefreshDatabase::class)` — matches every existing file in `tests/Feature/Modules/*`.
- After any PHP file changes, run `vendor/bin/pint --dirty --format agent` before considering a task done.
- Out of scope (do not implement): wiring into Vendor use cases, read-side API (list/mark-as-read), any domain-specific Notification class.

use App\Modules\Notification\Domain\Contracts\NotificationSenderInterface;
use App\Modules\User\Infrastructure\Models\User;
use Illuminate\Foundation\Testing\RefreshDatabase;
use Illuminate\Notifications\Notification;
use Illuminate\Support\Facades\Notification as NotificationFacade;

uses(RefreshDatabase::class);

function notificationSender(): NotificationSenderInterface
{
    return app(NotificationSenderInterface::class);
}

function fakeDatabaseNotification(): Notification
{
    return new class extends Notification
    {
        public function via(object $notifiable): array
        {
            return ['database'];
        }
    };
}

test('send delivers the notification to a single user', function () {
    NotificationFacade::fake();
    $user = User::factory()->create();
    $notification = fakeDatabaseNotification();

    notificationSender()->send([$user->id], $notification);

    NotificationFacade::assertSentTo($user, $notification::class);
});

test('send delivers the notification to multiple users at once', function () {
    NotificationFacade::fake();
    $users = User::factory()->count(3)->create();
    $notification = fakeDatabaseNotification();

    notificationSender()->send($users->pluck('id')->all(), $notification);

    $users->each(fn (User $user) => NotificationFacade::assertSentTo($user, $notification::class));
});

test('send skips ids that do not exist without throwing', function () {
    NotificationFacade::fake();
    $user = User::factory()->create();
    $notification = fakeDatabaseNotification();

    notificationSender()->send([$user->id, 999999], $notification);

    NotificationFacade::assertSentTo($user, $notification::class);
});

- [ ] **Step 5: Create the Domain contract**

Create `app/Modules/Notification/Domain/Contracts/NotificationSenderInterface.php`:

```php
<?php

namespace App\Modules\Notification\Domain\Contracts;

use Illuminate\Notifications\Notification;

interface NotificationSenderInterface
{
    /**
     * @param  int[]  $userIds
     */
    public function send(array $userIds, Notification $notification): void;
}
```

- [ ] **Step 6: Create the Infrastructure implementation**

Create `app/Modules/Notification/Infrastructure/NotificationSender.php`:

```php
<?php

namespace App\Modules\Notification\Infrastructure;

use App\Modules\Notification\Domain\Contracts\NotificationSenderInterface;
use App\Modules\User\Infrastructure\Models\User;
use Illuminate\Notifications\Notification;
use Illuminate\Support\Facades\Notification as NotificationFacade;

final class NotificationSender implements NotificationSenderInterface
{
    public function send(array $userIds, Notification $notification): void
    {
        $users = User::query()->whereIn('id', $userIds)->get();

        NotificationFacade::send($users, $notification);
    }
}
```

- [ ] **Step 7: Create the Service Provider and bind the interface**

Create `app/Modules/Notification/Providers/NotificationServiceProvider.php`:

```php
<?php

namespace App\Modules\Notification\Providers;

use App\Modules\Notification\Domain\Contracts\NotificationSenderInterface;
use App\Modules\Notification\Infrastructure\NotificationSender;
use Nwidart\Modules\Support\ModuleServiceProvider;

class NotificationServiceProvider extends ModuleServiceProvider
{
    /**
     * The name of the module.
     */
    protected string $name = 'Notification';

    /**
     * The lowercase version of the module name.
     */
    protected string $nameLower = 'notification';

    public function register(): void
    {
        parent::register();

        $this->app->bind(NotificationSenderInterface::class, NotificationSender::class);
    }
}
```
