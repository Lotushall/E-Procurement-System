# ความคืบหน้าของ TOR และค่างบประมาณที่ TOR ถือเอง

เมื่อ 2026-10-30 รีเซ็ต schema ของ TOR ให้เหลือแค่ `tors` กับ `tenders_projects` (ลบตารางเอกสาร TOR, ข้อเสนอ, คณะกรรมการพิจารณาผล และสัญญา ที่ออกแบบไว้ล่วงหน้าเมื่อ 2026-08-29 ออก เพื่อออกแบบใหม่ตอนถึงโมดูลนั้นจริง) และตัดสินว่าความคืบหน้าของ TOR คือ `draft → in_review → (revision_required) → approved → bidding → closed | no_bidder → awarded → completed` บวก `cancelled` ได้ทุกขั้นก่อน `awarded` ต้องผ่านการอนุมัติภายในก่อนประกาศเสมอ แต่**การประกาศคือการเปิดรับซองทันที** จึงไม่มีขั้น `published` แยก และไม่มีขั้น `evaluation` เพราะระบบไม่มีคณะกรรมการ/การให้คะแนน การตรวจคุณสมบัติและเลือกผู้ชนะเกิดในขั้น `closed` นอกจากนี้ `fiscal_year` และ `procurement_method` เป็นค่าของ TOR เองแม้โครงการจะมีค่าเดียวกันอยู่แล้ว เพราะ TOR อยู่ได้โดยไม่สังกัดโครงการ

## Consequences

- ค่าบน TOR กับโครงการที่ TOR สังกัดอาจไม่ตรงกันได้ ระบบไม่บังคับให้ตรงหรือสืบทอดกัน
- ขั้น `revision_required` (ส่งกลับแก้ไข) เป็นคนละเรื่องกับ **การแก้ไข (Revision)** ใน `CONTEXT.md` ที่หมายถึงบันทึกการเปลี่ยนค่า แม้ชื่อจะคล้ายกัน
- ถ้าวันหนึ่งต้องประกาศล่วงหน้าก่อนเปิดรับซอง ต้องเพิ่มขั้นใหม่ระหว่าง `approved` กับ `bidding` และแยกเวลาประกาศออกจาก `bidding_start_at`
